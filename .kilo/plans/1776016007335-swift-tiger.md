# Plan: UI Design Contract for Phase 1

**Created:** 2026-04-12
**Phase:** 1 (Authentication & Discovery Core)
**Status:** Planning

## Objective

Create a comprehensive UI design contract (UI-SPEC.md) for Phase 1: Authentication & Discovery Core. This phase enables anonymous parking discovery with location services, including GPS location, nearby parking results, interactive map, and navigation integration.

## Workflow Steps

### 1. Initialize
- Parse phase information for Phase 1
- Validate UI phase is enabled in config
- Check prerequisites (CONTEXT.md, RESEARCH.md)

### 2. Parse and Validate Phase
- Extract phase 1 details from ROADMAP.md
- Confirm phase exists and is frontend-relevant

### 3. Check Prerequisites
- Check for existing CONTEXT.md (user decisions from /gsd-discuss-phase)
- Check for existing RESEARCH.md (technical research)
- Display warnings if missing (non-blocking)

### 4. Check Existing UI-SPEC
- Look for existing 01-UI-SPEC.md in phase directory
- Handle update/view/skip options if exists

### 5. Spawn gsd-ui-researcher
- Create UI researcher agent with full context:
  - STATE.md (project state)
  - ROADMAP.md (roadmap)
  - REQUIREMENTS.md (requirements)
  - CONTEXT.md (if exists)
  - RESEARCH.md (if exists)
- Agent produces 01-UI-SPEC.md in phase directory

### 6. Handle Researcher Return
- Check for UI-SPEC COMPLETE or UI-SPEC BLOCKED
- Proceed to verification or exit if blocked

### 7. Spawn gsd-ui-checker
- Validate UI-SPEC.md against 6 quality dimensions
- Check compliance with user decisions and technical constraints

### 8. Handle Checker Return
- If VERIFIED: proceed to finalization
- If ISSUES FOUND: enter revision loop

### 9. Revision Loop (Max 2 Iterations)
- Re-spawn researcher with issues to fix
- Re-run checker validation
- Allow force approve, manual edit, or abandon after max iterations

### 10. Present Final Status
- Display approval confirmation
- Show next steps (/gsd-plan-phase 1)

### 11. Commit (if configured)
- Commit UI-SPEC.md with proper message

### 12. Update State
- Record session completion in state

### Output Files
- `.planning/phase-01/01-UI-SPEC.md` - UI design contract

## Agents Required

### gsd-ui-researcher
- **Model:** Configured for UI research
- **Input:** All project context files
- **Output:** UI-SPEC.md with design contracts for:
  - Anonymous parking discovery interface
  - Location permission and GPS handling
  - Nearby parking results display
  - Interactive map with clustering
  - Navigation integration (Google Maps deep-links)
  - Mobile-responsive design

### gsd-ui-checker
- **Model:** Configured for UI validation
- **Input:** UI-SPEC.md, user decisions, technical constraints
- **Validation:** 6 quality dimensions (completeness, consistency, feasibility, accessibility, mobile-first, brand alignment)

## Risk Assessment

### High Risk
- **Missing CONTEXT.md:** UI researcher will need to ask all design questions, potentially leading to suboptimal decisions
- **Missing RESEARCH.md:** Stack decisions not available, may lead to UI choices incompatible with technical architecture

### Medium Risk
- **Revision loop exceeds 2 iterations:** May require manual intervention or force approval
- **UI-SPEC blocked:** Critical design decisions unresolved, blocking phase planning

### Mitigation
- Prerequisites are non-blocking warnings
- Revision loop allows up to 2 iterations before manual options
- Force approve option available for non-critical issues

- **Revision loop (if needed):** 10-20 minutes
