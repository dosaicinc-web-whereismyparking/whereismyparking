## Layout and Hierarchy

- The default admin landing view is an action center, not a passive dashboard: KPI summary first, then pending review work on the same screen, matching Context decisions `D-01`, `D-03`, and `D-04`.
- Desktop uses a 12-column layout with 24px gutters. KPI cards span 3 columns each. The two highest-priority queues span 6 columns each directly below the KPI row.
- Tablet collapses KPI cards to 2 columns and stacks the priority queues vertically.
- Mobile is single-column only. Keep the KPI row scroll-free; stack cards and queues with 24px vertical separation.
- Keep a persistent admin header with page title, date/status context, and a single secondary export action. Do not place destructive actions in the header.
- Use tabs or segmented navigation below the overview for secondary surfaces in this order: `Overview`, `Listing Review`, `Payment Verification`, `Public Parking`, `Owners & Subscriptions`, `Exports`.
- Every queue row or card must expose a primary action, a secondary action, and a path to full detail without navigating away from the admin surface.

---

## Component Contract

- KPI cards: reuse the current `StatsCard` visual language, but keep card copy concise and sentence case. Required KPI set for the overview: total listings, pending approvals, active subscriptions, revenue, expired subscriptions, public/private split, rejected items, recent admin activity.
- Priority queue cards: the overview must show the next listing awaiting review and the next payment awaiting verification above the fold. Each card includes status, submitted time, owner identifier, and a `Review next item` CTA.
- Full-detail review surface: listing review opens a detail drawer or panel showing the full submission before approval or rejection. Required fields: name, address, coordinates, type, coverage, hours, vehicle types, notes, images, source metadata, owner phone, submission timestamp.
- Rejection modal: both listing and payment rejections use the same modal pattern with required preset category, optional note, and preview text explaining what the owner will see.
- Public parking management: use a table-first view with sticky filters and row actions. Create/edit happens in a side panel or full-screen modal with an embedded map for coordinates.
- Owners and subscriptions: use dense table rows with status badge, expiry date, grace-period state, linked listing count, and inline quick actions for activate, deactivate, renew, and extend.
- Export controls: keep export in a dedicated section-level toolbar. Exports are always scoped to the current filtered dataset and must label the date range in the export UI.
- Activity history: use a compact reverse-chronological list for recent admin actions and payment decision history. Each item shows timestamp, actor, target record, and action outcome.

---

## Interaction Contract

- After an approval or rejection, show inline success feedback for 2-3 seconds and automatically advance focus to the next item in the active queue.
- Approval actions are single-click with optimistic loading state, but completion is not reflected until the API confirms success.
- Rejection actions always require confirmation and a required category selection before submission. Do not allow a bare reject action.
- Queue filters must support status and date range everywhere relevant. Preserve the current filter state while the admin moves between tabs.
- CSV export must inherit active filters and show a loading/disabled state while export is preparing.
- Public parking delete is archive-only. Label the action `Archive record`, not `Delete permanently`.
- Subscription deactivate must warn that linked private listings will stop appearing in discovery until the subscription is active again.
- Grace-period subscriptions require a warning badge and appear before fully expired records in subscription management views.
- All primary row actions must remain reachable via keyboard tab order. Use visible focus rings with the accent color and never rely on hover-only disclosure for critical controls.

## Status Mapping

| Status | Visual treatment | Usage |
|--------|------------------|-------|
| Pending | `bg-amber-100 text-amber-800 border-amber-200` | New listing reviews, new payment verifications, unresolved admin tasks |
| Active | `bg-emerald-100 text-emerald-800 border-emerald-200` | Approved listings, active subscriptions, successful verifications |
| Rejected | `bg-red-100 text-red-700 border-red-200` | Listing rejections, payment rejections, blocked records |
| Grace Period | `bg-orange-100 text-orange-800 border-orange-200` | Subscriptions nearing expiry or temporarily recoverable |
| Archived / Inactive | `bg-slate-100 text-slate-700 border-slate-200` | Soft-deleted public parking, inactive subscriptions, disabled records |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding trims, inline metadata separators |
| sm | 8px | Compact control spacing, stacked label/value spacing |
| md | 16px | Default form gaps, cell padding on mobile, card internals |
| lg | 24px | Section padding, desktop card internals, queue separation |
| xl | 32px | Panel padding, page gutters on small desktop |
| 2xl | 48px | Major section breaks, empty-state breathing room |
| 3xl | 64px | Page-level vertical spacing on desktop overview |

Exceptions: 44px minimum touch target height for tab triggers, row actions, icon buttons, and modal footer buttons; 56px minimum height for primary queue CTA buttons.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F8FAFC` | Page background, overview canvas, table backdrop, empty states |
| Secondary (30%) | `#FFFFFF` | Cards, queue panels, tables, forms, drawers, modal surfaces |
| Accent (10%) | `#1A4A8A` | Primary CTAs, active tab state, focus rings, selected filters, progress-to-next-item affordances |
| Destructive | `#DC2626` | Reject actions, archive confirmations, destructive badges and warnings only |

Accent reserved for: `Review next item`, `Approve listing`, `Verify payment`, active navigation state, keyboard focus rings, selected date/status filters, and success-following progression cues. Do not use accent for neutral cards, table chrome, or passive badges.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Review Next Item |
| Empty state heading | No admin actions need review right now |
| Empty state body | Pending listings and payment verifications are clear. Review owners, manage public parking, or export the current dataset. |
| Error state | We couldn't load this admin section. Retry once. If it still fails, refresh the page and verify that your admin session is still active. |
| Destructive confirmation | Reject listing: Reject this listing? A rejection reason is required and the owner will be told exactly what to fix before resubmitting. Reject payment: Reject this payment? A rejection reason is required and the subscription will remain inactive. Archive public parking: Archive this public parking record? It will be removed from discovery but retained for audit and restore. Deactivate subscription: Deactivate this subscription? Linked private listings will stop appearing in discovery until the subscription is reactivated. |
