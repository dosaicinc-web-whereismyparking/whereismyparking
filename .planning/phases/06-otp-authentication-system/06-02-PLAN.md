# Plan 06-02: OTP Verification with Expiry and Lockout

Implement the verification logic that checks the OTP hash, enforces security constraints, and issues a successful session token.

## User Review Required

- **Session Type:** Supabase JWT session (issued via `auth.admin.createSession`)
- **Lockout Policy:** 3 failed attempts results in a 15-minute lockout

- [ ] `src/app/api/auth/verify-otp/route.ts` implements hash verification
- [ ] 5-minute expiry checked against `otp_sessions.expires_at`
- [ ] 3-attempt lockout logic updates `otp_sessions`

<action>
Create `src/app/api/auth/verify-otp/route.ts`:
1. Use `zod` to validate `phone` and `otp`.
2. Fetch the latest `otp_sessions` for the `phone`.
3. **Lockout Check:** If `locked_until > now()`, return 429 Error.
4. **Expiry Check:** If `expires_at < now()`, return 401 Error ("OTP expired").
5. **Hash Check:** Hash the input `otp` and compare with `otp_hash`.
6. **On Failure:**
   - Increment `attempts`.
   - If `attempts >= 3`, set `locked_until = now() + 15 minutes`.
   - Return 401 ("Invalid OTP").
7. **On Success:**
   - Reset `attempts` and `locked_until`.
   - Delete/invalidate the session.
   - Proceed to session issuance (Task 06-02-02).
</action>
