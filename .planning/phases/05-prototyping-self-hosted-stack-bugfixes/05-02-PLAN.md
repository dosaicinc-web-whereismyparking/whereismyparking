<task type="auto">
  <name>Task 1: Generate SQL migrations from Prisma schema</name>
  <files>supabase/migrations/03_initial_schema.sql</files>
  <action>
    - Ensure `supabase/migrations/` directory exists.
    - Run `npx prisma migrate diff --from-empty --to-schema-datamodel prisma/schema.prisma --script > supabase/migrations/03_initial_schema.sql`.
    - Manually audit the generated SQL file:
      - Add `CREATE EXTENSION IF NOT EXISTS postgis;` at the very top.
      - Ensure all tables (User, Listing, Subscription, AdminUser, AdminActivity, etc.) are included.
      - Check for any Prisma-specific artifacts that might not work directly in Supabase.
      - Verify RLS policies from previous migrations are either included or handled.
  </action>
  <verify>
    <automated>test -f supabase/migrations/03_initial_schema.sql</automated>
  </verify>
  <done>Full SQL schema migration file created and audited.</done>
</task>

<task type="auto">
  <name>Task 2: Configure self-hosted Supabase Docker stack</name>
  <files>docker-compose.yml, .env.supabase</files>
  <action>
    - Create a `docker-compose.yml` for self-hosted Supabase. Use the official template but simplify for local dev.
    - Essential services: db (postgresql + postgis), auth (gotrue), rest (postgrest), storage, kong (gateway).
    - Configure `.env.supabase` with default development secrets (e.g., `POSTGRES_PASSWORD=postgres`, `JWT_SECRET=dev-secret-at-least-32-chars-long`).
    - Map ports: 5432 (DB), 8000 (Kong/API).
  </action>
  <verify>
    <automated>docker compose config</automated>
  </verify>
  <done>Docker Compose configuration is valid and ready.</done>
</task>
